# 开发路线

## 0. 仓库初始化（本次）

- [x] 明确当前为需求待定的初始化仓库。
- [x] 提供目录职责、开发说明和协作模板。
- [x] 给出首个功能的需求入口和验收条件。

## 1. 确定最小目标

- [ ] 填写 PROJECT.md 的用户、问题、核心功能和输入输出。
- [ ] 创建一个包含可重复验收示例的功能 Issue。
- [ ] 记录技术栈选择和原因。
- [ ] 由维护者选择许可证。

完成条件：另一位开发者仅根据文档即可理解做什么、如何验收。

## 2. 交付第一个可运行闭环

- [ ] 在 src/ 中实现一个核心功能。
- [ ] 覆盖一个成功场景与一个无效输入或失败场景。
- [ ] 固定运行环境和依赖，补齐安装、启动、测试说明。
- [ ] 如需配置，提供不含秘密的配置示例。
- [ ] 从干净克隆验证上述命令。

完成条件：按 README 能启动，并复现首个 Issue 的预期结果。

## 3. 建立持续维护方式

- [ ] 根据已验证的测试命令配置 CI。
- [ ] 补充已知限制与故障排查。
- [ ] 按实际交付需要补充发布流程和版本记录。

完成条件：PR 能自动验证关键行为，发布步骤可重复执行。
