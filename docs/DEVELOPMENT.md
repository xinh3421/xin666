# 开发与验证指南

## 当前可做的事

克隆仓库后，用文本编辑器阅读和修改 Markdown 文档。当前无运行环境要求、依赖、应用入口、构建产物或自动化测试。

## 目录职责

- `src/`：核心功能实现；按选定语言组织模块。
- `tests/`：验证行为的测试与必要的脱敏样例。
- `docs/`：需求、开发指南与路线。
- `.github/`：任务与 PR 模板。

## 开始首个功能

1. 完成 [项目说明](PROJECT.md)。
2. 创建包含输入、输出和验收示例的 Issue。
3. 创建功能分支，例如 `feat/first-feature`。
4. 实现一个端到端可验证功能，增加成功与失败场景的测试。
5. 更新本页与根 README 的运行说明后提交 PR。

## 首个可运行版本必须补齐

以下是待提供的信息，当前不是可执行命令：

| 项目 | 必须记录的内容 |
| --- | --- |
| 环境 | 操作系统限制、语言及运行环境版本 |
| 安装 | 从干净克隆开始的依赖安装命令及锁文件 |
| 配置 | 必填和可选配置、默认值；需要时提供不含秘密的示例配置 |
| 启动 | 完整启动命令、入口、预期输出；服务项目还需地址和停止方式 |
| 测试 | 完整测试命令及关键验收用例 |
| 构建与发布 | 适用时提供构建、产物与发布步骤 |

## 验证要求

文档变更：检查仓库内相对链接存在、目录结构与文件一致、示例与当前状态一致。

功能变更：从干净克隆按文档安装并启动，执行测试，手动复现 Issue 的验收示例；在 PR 中记录实际结果。测试命令确定后再配置 CI。

不要提交凭据、个人数据或本地环境文件。新增工具时同步完善忽略规则。
